# 제4장 「비동기 작업 명령·해석 기술」 보고서 작성 지시문

작성 기준일: 2026-10-19  
확인 대상: `sketch-robot-runtime-main`의 현재 로컬 소스 및 문서(미커밋 변경 포함)

## 작성 요청

아래 구현 근거를 확인하고, **제4장 「비동기 작업 명령·해석 기술」의 연구개발 보고서 본문**을 한국어로 작성하라. 이 파일은 보고서 본문이 아니라 후속 작성자에게 전달하는 작성 지침이다. 아래 4.1~4.4의 제목과 순서를 유지하고, 각 절을 개발 목적 → 사용자 입력 → 공간정보 해석 → 명령 확인·전달 → 검증 결과와 한계의 흐름으로 서술하라.

핵심은 작업자가 원격 화면에서 지정한 의도를 로봇이 사용할 수 있는 공간 명령으로 해석하는 기술이다. UI 화면 소개나 ROS 노드 목록에 그치지 말고, 입력이 어떤 정보를 거쳐 무엇으로 확정되는지 설명하라. 공종 자율작업 모듈의 세부 제어 알고리즘은 연계 관계를 이해하는 데 필요한 범위만 기술하라.

## 반드시 지킬 사실과 범위

1. **코드 구현, 자동 시험, 시뮬레이션, 실제 카메라 연동, 물리 로봇 이동, 실제 시공 결과를 구분하라.** 테스트 파일의 존재는 시험 통과의 증거가 아니며, 문서의 과거 시험 수치를 현재 재실행 결과로 쓰지 않는다.
2. 본 지침 작성 시 코드·문서를 조사했으며 로봇·카메라 실행이나 테스트 재실행은 하지 않았다. 실물 롤러도장 성공과 H형강 각 면의 정밀 측정 성능은 이번 조사만으로 확정할 수 없다. 해당 결과는 원자료를 확보한 경우에만 서술하라.
3. `docs/PLATFORM_RUNTIME.md`에는 2026-10-16 시뮬레이션 롤러 검증이 기록되어 있다. 상용 왼팔·RB10의 통과와 상용 오른팔의 최신 미통과를 구분한다. 이를 물리 로봇 도장 성공이나 모든 구성의 완료로 바꾸지 않는다.
4. **최신 Spray 흐름은 ZED 전용이며 D405 접근·정밀 측정을 수행하지 않는다.** D405 정밀 측정은 Paint 흐름과 이전 다중면 측정 기능에서 구분해 설명한다. 예전 문서의 D405 기반 설명을 현재 Spray 동작으로 옮겨 쓰지 않는다.
5. **내화뿜칠 경로 생성과 실행은 공종 자율작업 모듈의 범위로 명시하라.** 저장소에 뿜칠 경로 생성·실행 코드가 있어도 본 절의 핵심 성과는 면 인식·선택·공간 명령 전달이다. 논리적 역할 구분을 별도 외부 시스템과의 통합 완료로 과장하지 않는다.
6. 다중 평면 검출과 웹(web)·상부 플랜지·하부 플랜지의 자동 의미 분류는 다르다. 조사한 코드에서 확인한 것은 ROI 내 기하 평면 추출·후보 선택이다. 각 후보가 어느 구조 부위인지 자동 분류한다는 주장은 별도 구현·실험 근거가 있어야 한다.
7. 용접은 완전 미구현이 아니다. 이음선 명령 계약, RGB-D 사용자 지정선의 3D 구성, UI 및 시뮬레이션 기록이 존재한다. 확인된 범위는 짧게 인정하되, 실환경 용접 명령 연계·실제 용접 출력·시공 품질은 증거가 없으면 향후 개발 방향으로 기술한다.
8. 설계 문서의 목표와 실제 구현을 구분한다. 문서가 충돌하면 현재 코드와 해당 실행 모드, 날짜가 명시된 원자료를 대조하고 미확인 사항을 남긴다. 미확인 수치·성공률·정확도를 만들지 않는다.

## 4. 비동기 작업 명령·해석 기술

장의 도입부에서는 작업자가 작업대상과 의도를 지정하고, 시스템이 공간정보를 해석한 뒤 확인된 명령을 공종별 자율작업 모듈에 전달하는 구조를 설명하라. 여기서 비동기는 사용자가 로봇의 매 순간 동작을 연속 조종하는 대신 작업 단위로 입력·확정하고 처리·실행 상태를 회신받는 방식으로 정의하라. 영구 작업 큐, 오프라인 예약 실행, 자동 재시도 등 확인되지 않은 기능까지 포함하지 않는다.

## 4.1 공통 명령·해석 절차

다음 순서를 중심으로 작성하라.

**작업대상 제시 → 사용자 입력 → 공간정보 해석 → 명령 확인 → 공종 자율작업 모듈 전달**

1. **작업대상 제시:** 카메라 영상과 검출 평면·윤곽·선택 상태를 표시하고, 작업자가 대상과 유효 영역을 확인하는 과정을 설명한다.
2. **사용자 입력:** 대상 ROI, 작업평면, 작업영역, 작업경로를 서로 다른 입력으로 구분한다. 대상 외곽선과 실행 경로를 혼동하지 않는다.
3. **공간정보 해석:** 깊이·카메라 내부 파라미터·좌표 변환·평면 위치와 법선·경계 정보를 결합하는 과정을 설명한다. 2D 스케치는 사용자 입력 방식이고, 3D 정보는 해당 입력의 공간적 의미를 정하는 근거임을 밝힌다.
4. **명령 확인:** 후보 면 선택, 작업영역 확정, 경로 미리보기와 실행 준비 상태 확인, 명시적 작업 시작을 구분한다. 측정을 위한 로봇 접근과 최종 작업 실행도 구분한다.
5. **모듈 전달:** 확정된 공간정보와 식별자·상태를 전달하고, 실행 모듈이 이를 재검증한 뒤 공정 동작을 수행하며 진행·완료·거부 상태를 회신하는 구조를 설명한다.

2D 영상 스케치는 보이는 평면상의 대상·영역·선을 지정하는 데 적용하고, 깊이/점군·평면·3D 장면 정보는 위치·자세·충돌 환경 해석에 사용한다고 정리하라. 3D 환경을 활용한다는 이유만으로 임의 공간에서 자유로운 3D 스케치 편집을 구현했다고 쓰지 않는다. 물리 센서와 가상 센서, CAD 시험 입력도 구분하라.

수정 방식은 되돌리기·모두 지우기·재선택·재확정으로 설명하라. 대상 삭제 시 평면 목록·선택도 초기화되고 취소된 요청의 늦은 응답을 무시하는 동작, 영역·경로 단계의 수정은 해당 단계 입력을 대상으로 하는 동작을 구분하라. 평면·공정·구성 변경 시 기존 경로의 재사용을 막는 식별 검사를 포함한다.

역할 분담은 다음 표로 요약하라.

| 원격 인터페이스와 명령 해석 | 공종 자율작업 모듈 |
| --- | --- |
| 대상·면·영역·경로 입력, 수정, 공간정보 연결, 명령 미리보기와 확정 | 전달된 명령의 유효성 검사, 공종 경로·자세 계획, 로봇 실행과 공정 제어 |
| 실행 요청 및 상태 표시 | 진행·완료·실패·중단 상태 회신 |

## 4.2 도장: 2D 스케치의 3D 경로 변환 및 실행

### 포함할 내용

- Web GUI에서 대상 선택 → 평면 측정 → 작업영역 확정 → 직선·자유선 경로 입력 → 미리보기·실행 확인의 흐름을 설명한다. 영역 자동 채우기는 수동 스케치와 별도의 입력 보조 기능으로 짧게 언급한다.
- ZED는 대상·초기 작업면 정보를 제공하고, D405는 선택 작업면과 작업영역의 근접 정밀 측정에 사용되는 역할을 설명한다. 두 센서의 모든 프레임을 상시 융합한다고 쓰지 않는다.
- 원영상 픽셀의 광선–평면 교차와 정면화 화면(`wall_front`)의 평면 좌표 매핑을 구분한다. 입력 프레임에 따라 구현이 다르므로 모든 픽셀에 깊이를 직접 대입하는 단일 방식으로 설명하지 않는다.
- 개념식은 필요할 때 `p_base = R · p_camera + t`, `p_surface = o + a·e1 + b·e2` 수준으로 제시하고, 각 좌표계·단위·입력 화면과 연결한다. 식을 해당 코드의 정확한 구현이라고 단정하기 전에 변환 분기를 확인한다.
- 3D 경로의 위치·법선·진행 방향을 바탕으로 공구 자세와 공정 구간을 구성하고, 로봇 계획·실행 모듈에 전달하는 과정을 설명한다. 공간 경로 생성과 로봇 관절 궤적 계획은 구분한다.
- 작업영역 포함 여부, 선택 면·측정 세대·경로 식별 일치, 계획 상태 확인 등 잘못된 명령 해석을 방지하는 조건을 설명한다. 제어기 내부 구현은 이 절의 중심으로 확대하지 않는다.

### 실환경 롤러도장 실행 및 명령 해석 결과

이 소제목은 유지하되 실물 실행 증거가 없으면 미확인 상태와 필요한 자료를 명시하라. 확인한 최신 플랫폼 문서는 시뮬레이션 성과를 포함하며 물리 로봇 실행 증거를 대신하지 못한다.

결과는 입력 영상·스케치, 대응 3D 경로, 로봇 실행 기록, 실제 도장면 사진을 동일 시험으로 연결해 제시하라. 로봇 모델·EOAT·카메라·보정·시험일·입력 영역·획 수·성공/거부 조건을 기록한다. 변환 오차, 경로 추종 오차, 접촉력, 도막 품질은 서로 다른 지표이며 실제 측정된 항목만 보고한다. 실물 자료가 없으면 시뮬레이션 결과를 별도 문단으로 제한해 제시한다.

## 4.3 내화뿜칠: 다중 작업면 인식·선택 및 명령 전달

### 포함할 내용

- H형강의 웹 및 상·하부 플랜지를 대상 작업면으로 설명하고, 사용자 ROI 내에서 여러 평면 후보를 분리하여 중심·법선·윤곽과 식별자를 산출하는 흐름을 서술한다.
- 현재 소스는 정렬 깊이 입력에서 RGB/깊이 연결 영역을 나눈 뒤 평면을 적합하고, 비정렬 점군에서는 반복 RANSAC을 사용하는 분기가 있다. 과거 문서의 “전체 ROI 반복 RANSAC” 설명만을 현재 알고리즘으로 쓰지 않는다.
- 후보 번호·윤곽을 보고 작업자가 필요한 면을 선택하고, 작업할 면을 활성화한 뒤 영역을 지정·확정하는 과정을 설명한다. 여러 면을 선택하는 기능과 여러 면의 시공을 자동 연속 실행하는 기능은 다르다.
- 위치·자세 측정은 평면 중심과 법선 등 실제 제공 정보를 중심으로 기술한다. 법선만으로 면 내 회전까지 유일하게 정해지는 완전한 6자유도 자세를 얻었다고 쓰지 않는다.
- 최신 Spray는 ZED 대상 잠금·표면 상태로 면을 확정한다. D405 정밀 측정 기능을 소개해야 한다면 Paint/이전 공통 다중면 측정과 구별해 별도 문장으로 설명한다.
- 확정된 면·영역을 내화뿜칠 자율작업 모듈이 사용할 수 있도록 전달하는 구조를 기술한다. 기존 토픽 기반 연결을 확인된 범위로 제시하고, 별도 외부 모듈과 통합 시험을 마쳤다는 주장은 근거가 있을 때만 쓴다.

전달 정보는 공간 기하와 식별 정보를 나누어 설명하라. 공간 기하는 기준 좌표계, 평면 위치·법선, 선택 영역 경계이며, 식별 정보는 대상/평면 세대와 작업영역·선택 식별자다. 하나의 메시지에 모두 들어간다고 가정하지 말고 관련 상태와 요청의 결합 관계를 확인한다.

실제 구현 예로 `/perception/target_planes`, `/painting_system/select_planes`, `/painting_system/activate_plane`과 `/painting_system/zed_work_area_request`를 활용할 수 있다. 작업영역 요청의 `source`, `plane_generation_id`, `header`, `pixels`와 같은 선택의 `/work_area_pixels`가 동일 stamp·좌표를 사용하며, 관련 표면 상태의 식별자와 대조되는 구조를 설명한다. 전체 토픽 나열은 부록으로 제한한다.

**이 절에 반드시 포함할 문장:**

> 본 기술의 범위는 작업면의 인식·선택, 공간정보 해석 및 확정 명령 전달이며, 내화뿜칠 경로 생성과 로봇 실행은 공종 자율작업 모듈의 범위로 구분한다.

### 다중평면 검출·선택·정밀측정 검증 결과

검출, 사용자 선택, 측정 품질, 명령 전달을 별도로 평가하라. 웹·상하부 플랜지의 대응이 확인된 영상, 누락·과분할 여부, 선택 유지·변경 결과, 법선/위치 오차 또는 평면 잔차, 이전 면 요청의 거부 여부 등을 자료가 있는 항목에 한해 제시한다. 평면 적합 잔차는 외부 기준 대비 절대 위치 정확도와 다르다.

합성 점군·모의 ROS·브라우저 시험은 소프트웨어 검증으로 표시하고, 실제 ZED 깊이 품질과 실제 D405 정밀측정 성능으로 바꾸지 않는다. 현재 자료로 H형강 세 부위의 정량 검출률·정밀도가 확인되지 않으면 `[실험자료 확인 필요: 면별 검출 및 위치·법선 측정 결과]`를 남긴다. 분사량·도포 두께·피복 품질은 이 절의 명령 해석 성능으로 집계하지 않는다.

## 4.4 용접 작업 명령으로의 확장

이음선, 시작점·종료점, 진행 방향을 지정하는 명령 형태와 용접 자율작업 모듈에 필요한 정보를 중심으로 작성하라.

- 가능한 입력 형태: 영상에서 열린 이음선 점열 지정, 시작점·종료점 및 진행 방향 지정. 각 UI 조작이 실제 지원되는지는 `weld_workflow.js`와 입력 노드에서 대조하고, 미확인 형태는 확장안으로 쓴다.
- 확인된 기반: `Seam`의 `points_xyz`·기준 방향/자세 정보, `SeamCatalog`의 프레임·세대·출처 계약, 동일 RGB-D 노출의 사용자 지정선을 역투영하고 등록 좌표계로 옮기는 처리. 깊이 누락·불연속 및 방향 모호성을 거부하는 조건도 존재한다.
- 연계 정보: 이음선 3D 점열과 순서, 기준 좌표계와 단위, 영상/대상 식별·보정 정보, 자세 기준, 공정 설정 및 명령 확정 상태. 현재 필드와 향후 추가 필드를 구분한다.
- 검증 경계: CAD fixture 기반 가상 용접선 추종·위빙 기록은 실제 용접선 자동 인식이나 실물 용접 출력 검증이 아니다. 물리 카메라 기반 연계도 코드 존재와 현장 통합 성공을 구분한다.
- 향후 방향: 실환경 이음선 지정과 3D 대응 검증, 용접 모듈 인터페이스 확정, 실제 장치 연결, 공정 실행 및 품질 평가. 해당 결과의 증거가 확보되기 전까지 완료 성과로 쓰지 않는다.

권장 서술: “용접 작업으로의 확장을 위해 사용자 지정 이음선의 공간 표현과 모듈 전달을 위한 기반을 구성하였다. 확인된 구현 및 시뮬레이션 범위와 별도로, 실환경 용접 명령 연계 및 실제 공정 검증은 추가 확인·개발 항목으로 구분한다.” 실제 원자료 확인 결과에 맞게 강도를 조정하라.

## 최종 산출물 형식

1. 위 4.1~4.4 구성의 보고서 본문. 문장 종결은 ‘구현하였다/확인하였다/계획이다’를 증거 수준에 맞게 구분한다.
2. 공통 명령 절차도 1개, 도장 2D–3D 변환 도식 1개, 다중평면 선택·전달 도식 1개를 제안한다. 캡처가 없으면 필요한 그림 목록과 캡션을 제시하고 가짜 실험 이미지는 만들지 않는다.
3. ‘기능–입력–해석 결과–전달 대상–검증 수준–근거’ 표와 ‘추가 확인 자료’ 목록을 첨부한다.
4. 정량 결과마다 시험일·실행 모드·대상 구성·원자료 경로를 붙인다. 확인되지 않은 결과를 채우기 위해 추정값을 넣지 않는다.
