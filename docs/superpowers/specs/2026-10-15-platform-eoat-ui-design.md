# 실행 환경·로봇 플랫폼·공정 선택과 EOAT 자동 장착

**2026-10-16 최신 재검증:** 왼팔·RB10 정상 도장/접촉 중 중단 통과는 유지한다.
오른팔은 기존 작업 종료 후 GPU 단독 관측 구간에서 재시험했지만, 첫 획 힘 유지
통과 뒤 두 번째 PAINT 진입의 `PAINT_NOMINAL_MEASURED_STATE_STALE`로 거부됐다.
GPU 공유만으로 설명할 수 없으며 명목 시작점 재검사의 source/clock 시각 경계가
추가 진단 대상이다. 별도 중단 시험은 이후 다른 계정 작업이 시작되어 접촉 전에
정리했다. 오른팔 정상·loaded cancel 및 실제 카메라 mixed 9조합은 미완료다.
이번에는 제어 코드를 변경하지 않았다. [실행 문서](../../PLATFORM_RUNTIME.md)의
오른팔 단독 GPU 재검증 절에 원자료와 판정 범위를 기록했다.

**최신 확정 기준 (2026-10-15):** 상용로봇 플랫폼은 **왼팔 내화뿜칠 spray v2 / 오른팔 Hongik V4 용접 EOAT + 레이저 센서**로 구성한다. 용접·뿜칠 대상체는 H_STEEL_USD다. 이 구성을 기본 장착 사양으로 사용한다. 레이저 센서 형상·CAD 프레임은 포함하며 실제 데이터 수신은 별도 연결 대상이다. 공정 선택에 따른 공구 교체 기능은 아래 계획대로 유지한다.

상태(2026-10-15 구현 체크포인트): 분리 worktree에서 개발해 주 작업 폴더에 통합한 선택·EOAT 생성·적용 트랜잭션·
8081 UI·공통 simulator/ROS 런처·mixed 카메라/측정 장면·선택 팔 롤러 제어 경로를
구현하고 코드/단위 회귀를 기록했다. **코드 구현 완료, 라이브 검증 일부 미완료 (live
verification incomplete)**이며 18개 실행 조합, 실제 카메라 연결, 두 PAINT 획의
접촉력 유지·중단을 완료로 판정하지 않는다. 새 자산은 `.runtime/platform/assets/`에
생성하며 기존 운영 `isaac_assets`는 유지한다. Git 작성자 정보가 없어 커밋하지 않았다.
세부 상태는 [구현 계획 체크포인트](../plans/2026-10-15-platform-eoat-ui.md)와
[실행 문서](../../PLATFORM_RUNTIME.md)를 따른다.

시뮬레이션 9개 구성은 각각 관절 이동·복귀·취소 후 실측 정지와 비활성 팔
유지를 통과했다. 상용 왼팔·오른팔 용접은 가까운 `IfcFastener_WELD_004`를
work/travel 0°/15°로 실행해 위빙·추종 판정을 통과했다. RB10 용접도 동일 CAD
작업선을 60°/0°로 실행해 최대 위치 오차 0.443 mm로 통과했다. 상용 양팔과 RB10
뿜칠은 실제 렌더 RGB-D 선택부터 실행·실측 추종까지 통과했다. 롤러의
두 PAINT 획 힘 유지·이탈은 상용 왼팔에서 통과했다. 오른팔·RB10의 전체
롤러 실행과 세 구성의 접촉 중 중단은 아직 통과하지 못했다.
mixed 9개와 물리 로봇은 `not_run`이며 전체 18개 조합 완료로 집계하지 않는다.
주 작업 폴더의 전체 Python 회귀는 1,852 passed / 18 skipped, JS는 140 passed다.
후속 변경의 집중 검증과 최신 실행 증거·한계는 [실행 문서](../../PLATFORM_RUNTIME.md)를 따른다.


후속 코드에는 명목 geometry 없는 동적 target registry, 고정 선택 프레임 기반
평면 추출, 표면 바깥쪽 weld 법선, D405 refined mesh의 정확한 parent/new revision과
Isaac·MoveIt dual ACK 장벽, 취소 종료 전 설정 변경 차단을 반영했다. 이는 물리
카메라나 전체 공정의 검증 완료를 뜻하지 않는다.

## 사용자 의도와 확정한 방향

- 공정과 사용할 팔을 선택하면 해당 팔에 롤러도장·내화뿜칠·용접 EOAT를 장착한다.
- 공구 형상, 장착 변환, TCP, 충돌 모델과 실행 설정을 함께 변경한다.
- 설정 적용 시 시뮬레이션과 관련 ROS 프로세스를 재시작한다.
- `http://127.0.0.1:8081/` 기본 UI를 아래의 실행 모드·플랫폼·공정으로 정리한다.
- 사용자에게 보이는 Construct 명칭은 **상용로봇 플랫폼**으로 바꾼다.
- 상용로봇 플랫폼과 용접 EOAT는 사용자가 추가 지정한 `hongik_urdf_v4_2026-10-13.zip`을 기준으로 한다. 이전 오른팔 공구 선택을 이 원본으로 대체한다.
- 용접·내화뿜칠의 시뮬레이션 대상체는 `h_steel_USD.zip`의 `Steel Structure.usdc`로 교체한다. 일부 시뮬레이션의 실제 측정 대상은 실카메라 입력을 사용하며 이 고정 USD로 대신하지 않는다.
- 일부 시뮬레이션은 내화뿜칠·용접·롤러도장 모두의 필수 지원 범위이다.
  뿜칠만 연결한 상태로 전체 기능을 완료 처리하지 않는다.
- 상용로봇 플랫폼의 왼팔·오른팔 모두 롤러도장을 지원한다. 롤러 장착뿐 아니라
  스케치 경로 실행과 시뮬레이션 접촉·힘 제어까지 포함한다.

## 공구와 팔의 분리

공구 카탈로그는 세 프로필을 갖는다.

- 롤러도장: 기존 롤러, AFT200, D405 구성과 접촉 기준점.
- 내화뿜칠: 새 spray v2 CAD, 명목 노즐 TCP와 분사축. 기존 D435는 포함하지 않는다.
- 용접: Hongik v4 ZIP의 브라켓·토치·레이저 센서 공구. 오른팔 D435는 없다.
  TCP는 컨택트 팁 끝면 중심이며 +Z가 와이어 방향이다. 기존 150 mm 시험 토치는
  추가하지 않는다. 와이어 돌출은 별도 공정값으로 다루며 실측 교정값과 혼동하지 않는다.

원본은 `assets/construct/hongik_v4/source/`와 `assets/construct/h_steel/source/`에
보존하고 각각 `source.json`에 ZIP·파일 SHA256을 기록했다. Hongik ZIP은 델타
패키지이므로 기존 `src/construct_description`의 몸체·팔·헤드 메시를 함께 사용한다.
14개 구동 관절의 정의는 기존과 동일하다. 왼팔은 새 spray v2 공구를 유지한다.
ZIP 이름은 v4이나 내부 문서/URDF 이름은 `hongik_v2 r4`이며 실제 내부 이름을 보존한다.

H형강은 Z-up, 미터 단위이며 크기는 약 1.03 × 0.80 × 1.516 m이다. 23개 메시와
2352개 삼각형을 그대로 유지한 정적 충돌 모델을 생성했다. 작업체 배치는 별도
변환으로 관리하며 실제 설치 좌표로 교정되었다고 표시하지 않는다. 기존 testbed의
숨겨진 충돌 형상과 예전 H-beam 박스를 새 장면에 남기지 않는다.

팔별 장착 상태와 이번 작업의 활성 팔은 별도로 저장한다. 기본 장착은
왼팔 내화뿜칠 / 오른팔 용접이며, 선택한 팔의 공구만 변경한다. 반대쪽 팔은
이전 장착을 유지한다. 양팔에 같은 공구를 장착할 수 있지만 이번 범위에서
작업 실행은 한 번에 한 팔만 한다.

공구마다 장착 변환·TCP·도구축·접촉 링크·카메라 링크·형상/관성 출처를 정의한다.
팔마다 링크 이름을 구분하여 같은 EOAT 두 개를 장착해도 충돌하지 않게 한다.
공구를 다른 팔로 옮길 때 메시를 임의로 좌우 반전하지 않고 장착 좌표 변환을
사용한다. 기존 RB10/RB20 공구 정의를 공통 원본으로 재사용한다.

URDF, SRDF, USD, EOAT 프로필과 실행기는 하나의 장착 구성에서 생성한다.
교체 전 공구의 링크·충돌 제외쌍·추가 토치를 남기지 않는다. 새 공구의 접촉
예외를 다른 공구에 그대로 적용하지 않는다.

## 설정 적용과 실행

1. UI에서 설정 초안을 만들고 서버가 조합 지원 여부를 검증한다.
2. 작업 실행 중에는 공구 교체를 차단한다. 대기 중인 시스템에는 적용/재시작을 제공한다.
3. 관련 프로세스를 종료한 뒤 새 구성 자산을 별도 위치에 생성·검증한다.
4. 검증된 자산 묶음을 적용하고 Isaac Sim, MoveIt, 인식기, 실행기를 시작한다.
5. 모든 구성의 모델 식별자와 충돌 기준이 일치한 뒤 준비 상태를 표시한다.
6. 이전 대상·영역·경로는 무효화한다. 공구 교체만으로 작업을 자동 실행하지 않는다.

생성에 실패하면 이전 자산을 보존하고 실패 원인과 실제 적용 상태를 보여준다.
다른 공구·모드로 조용히 대체하여 시작하지 않는다. 동일 구성의 검증된 자산은
내용 해시로 재사용할 수 있다. 실행 중 즉시 형상을 교체하는 기능은 이번 범위에서 제외한다.

## 현재 구현과 지원 범위

확인 근거: `runtime_selection.py`, `runtime_apply.py`, `eoat_catalog.py`,
`prepare_platform_assets.py`, `platform_simulation.launch.py`, `platform_stack.py`,
카메라/장면/RGB-D provider와 UI/roller 검증 기록.

- simulation/mixed × commercial left/right 또는 RB10 single × spray/weld/paint의
  18개 코드 경로를 구성한다. 지원 표시와 실제 실행 성공은 별도다.
- 활성 팔 EOAT를 공정에 맞게 생성하고 비활성 팔 장착은 보존한다. 기본은
  왼팔 spray v2 / 오른팔 Hongik v4 토치·레이저 CAD다. 실제 레이저 수신은 별도다.
- 선택 팔의 실제 Isaac 반력, 중력, tare, admittance/JTC 연결을 구현했다.
  실측 20 N 유지·두 PAINT 획·중단/후퇴는 라이브 검증이 남아 있다.
- mixed는 실제 Outpost ZED와 도장용 D405의 고정 측정 registration, 동일 RGB-D
  identity와 새 입력, Isaac/MoveIt 같은 측정면 revision ACK를 요구한다. 물리
  카메라의 움직이는 자세 adapter는 아직 없으므로 가상 손목으로 대체하지 않는다.
- simulation weld fixture는 실제 CAD face의 노출된 중선·외향 법선을 사용하고
  가림/방향 모호성을 거부한다. mixed 용접은 사용자가 고정한 실제 RGB-D frame의
  열린 진행선을 역투영하며 필요 시 명시한 `reference_up`을 받는다.
- 기본 revisioned apply에서는 real RB10도 차단한다. 기존 물리 `work` /
  `spray_motion_test`는 종료 후 고급 설정에서 사용하고 기존 인터록을 유지한다.
  상용플랫폼 실환경·실환경 용접 드라이버는 제공하지 않는다.
- 기존 RB20은 정확한 별도 모델/실행 프로필로 유지한다. RB20 실측 결과를 새
  상용플랫폼 롤러 실행 결과로 대체하지 않는다.

### 세 공정의 일부 시뮬레이션과 기존 기능 재사용

일부 시뮬레이션의 공통 계약은 **실제 카메라로 작업 정보를 구성하고 Isaac Sim의
선택한 로봇·팔·EOAT가 실행하는 것**이다. 상용로봇 플랫폼과 RB10 베이스의
세 공정을 대상으로 하며, 실제 로봇 이동이나 실제 분사·용접 출력을 요구하지 않는다.

| 공정 | 실제 카메라에서 구성하는 정보 | 가상 로봇에서 검증하는 동작 |
| --- | --- | --- |
| 내화뿜칠 | 작업면·법선·스케치 영역 및 경로 | 노즐 자세·이격거리·도포 경로 이동 |
| 용접 | 사용자가 지정한 용접선의 3D 위치·방향 및 주변 작업면 | 토치 자세·위빙·용접선 추종 |
| 롤러도장 | 작업면·법선·작업영역, 필요한 D405 정밀 측정 | 접근·롤러 접촉·목표 접촉력 유지·도장 경로 이동 |

용접은 고정 시험용 용접선으로 대체하지 않고 실제 카메라 입력에서 지정된 3D
용접선을 기존 실행기에 전달한다. 자동 용접선 인식 전체를 새로 개발하는 것은
이 요구와 별개이며, 사용자 지정과 깊이 기반 3D 구성을 우선 재사용한다.
롤러도장은 실제 측정 작업면을 같은 좌표의 가상 접촉면으로 구성하고 Isaac의
접촉 반력으로 힘 제어를 검증한다. 실제 접촉력 측정으로 표시하지 않는다.
세 공정 모두 측정한 작업 형상을 가상 장면과 MoveIt 충돌 장면에 일치시킨다.

실제 ZED의 Outpost 수신, 평면 선택, 스케치 및 뿜칠 경로 생성은 기존
`zed_preview.launch.py`와 실장비 뿜칠 흐름에서 재사용한다. 새 카메라 처리기를
만드는 작업으로 산정하지 않는다. `zed_preview`는 로봇 실행이 없는 경로 미리보기이고,
`spray_motion_test`는 실제 로봇 이동이므로 어느 쪽도 그대로 일부 시뮬레이션으로
이름을 바꾸지 않는다.

공통 연결을 재사용하면서 세 공정의 실제 카메라 입력과 기존 Isaac 실행기를 연결한다.
추가 작업은 가상 카메라 실행 분리, 실제 카메라 선택, 실제 카메라에서 가상 로봇
기준으로의 좌표 정합, 실제 영상 시각과 시뮬레이션 시각의 처리, 통합 실행 검증이다.
기존 일반 런치의 `use_isaac_sim`/`use_fake_hardware` 카메라 결합은 유지하되,
신규 platform 런치는 명시적 실행 모드에 따라 Isaac 렌더 카메라와 실제 Outpost
카메라를 분리한다. 원래의 인식기/경로 생성기는 선택한 설정으로 재사용한다.
기존 카메라 처리와 가상 로봇 실행 코드는 있으나, 확인한 문서만으로 과거의
실제 ZED + Isaac 로봇 통합 실행 성공 여부를 확정하지 않는다.

UI의 세 모드는 환경의 분류이며 모든 플랫폼·공정 조합의 지원 완료를 뜻하지 않는다.
서버가 지원 상태와 이유를 제공하고 UI와 직접 API 호출에 동일하게 적용한다.
지원되지 않는 조합에는 ‘미지원’ 또는 구체적인 미연결 원인을 표시하고 시작을 차단한다.
실환경에서는 실제 장착 EOAT와 보정 정보가 일치해야 하며 UI 선택을 물리적
공구 교체 완료로 취급하지 않는다.

이번 구현 범위는 새 UI, 상용로봇 플랫폼의 양팔 EOAT 선택과 세 공정의
시뮬레이션 실행, 두 플랫폼에서 세 공정의 일부 시뮬레이션 지원이다.
구현 순서는 공통 기능 재사용에 따라 나눌 수 있지만, 일부 공정을 ‘미지원’으로
남겨두는 것을 해당 필수 범위의 완료로 간주하지 않는다. 장비가 없어 실제 카메라
통합 검증을 수행하지 못한 경우에는 구현 완료와 장비 검증 미완료를 구분해 보고한다.
기존 실환경 실행 경로는 보존한다. 신규 실제 로봇 드라이버나 분사·용접 장치
드라이버를 이 기능의 일부로 새로 구현하지 않는다.

일부 시뮬레이션은 실제 카메라를 가상 로봇 기준에 정합하는 보정과 영상 수신이
검증된 조합부터 활성화한다. 실제 손목 카메라의 위치를 가상 손목 위치로
간주하지 않는다. 필요한 실제 카메라 자세를 제공할 수 없는 구성은 준비되지
않은 것으로 표시한다.

롤러 장착과 롤러 힘 제어는 별도 검증 항목이다. 상용로봇 플랫폼에서 접촉 힘
측정·센서 프레임·제어기 연결이 완료되기 전에는 장착/경로 확인만 가능하다고
표시하고 정상 도장 실행 가능 상태를 내보내지 않는다. 이는 개발 중 상태이며,
상용로봇 플랫폼 롤러도장의 최종 완료 기준은 아니다. 최종적으로 양팔 각각에서
선택한 롤러의 접촉 링크, 센서 좌표계, 제어기와 작업면을 연결해 접근·접촉·
목표 접촉력 유지·경로 추종·중단·이탈을 검증한다. 기존 RB20의 측정 기반
롤러 시뮬레이션을 재사용하되 로봇 관절 이름과 단일 TCP 가정을 양팔에 맞춘다.

## 검증 기준

- 양팔 × 세 공구의 모델 생성, 동일 공구 양팔 장착, 공구 교체 후 잔여 링크 제거.
- TCP·도구축·접촉 링크가 선택한 공구 및 팔과 일치하고 모든 SRDF 참조 링크가 존재함.
- Isaac과 MoveIt이 동일 구성을 사용하며 실행기의 충돌 기준 확인이 성공함.
- UI 모드·플랫폼·팔·공정 선택, 적용 대기/완료/실패 상태, 재접속 시 구성 복원.
- 미지원 조합과 실행 중 교체는 UI와 API 모두에서 차단됨.
- 기존 RB10/RB20 실행 계약과 사용자 수정 중인 스케치 공정 흐름이 유지됨.
- 상용로봇 플랫폼 양팔 각각에서 롤러도장 실행과 시뮬레이션 접촉력 유지,
  작업 중단 및 이탈을 검증함. 롤러 모델 표시만으로 통과 처리하지 않음.
- 일부 시뮬레이션에서 두 플랫폼의 세 공정 모두 실제 카메라 작업 입력부터
  가상 로봇 실행까지 연결됨. 상용로봇 플랫폼은 양팔을 각각 검증함.
- 용접은 실제 영상에서 지정한 용접선을 사용하고, 롤러도장은 측정 작업면과
  가상 접촉면을 일치시킴. 실제 손목 카메라 자세를 가상 손목 자세로 대체하지 않음.
- 실제 카메라 모드는 실제 영상·보정 확인으로, 롤러 힘 제어는 접촉 측정으로
  검증한다. 모의 입력 테스트를 실제 장비 검증으로 보고하지 않는다.
