## 1. 사용자가 정한 범위

새 컴퓨터에 SNUCEM_Robot_22.04를 먼저 설치한다. 그 환경의 카메라, 다중 평면 추출,
로봇·공구 3D 모델, MoveIt, 드라이버를 사용한다.
우리 웹 화면, 면 선택, 작업영역, 자유선·직선 경로, 자동 채우기, 경로 검증,
로봇 자동 실행·중단을 작은 추가 패키지로 설치한다.
공정은 내화뿜칠(Spray)만 지원한다.

기존 sketch-robot-runtime main은 유지한다. 새 독립 저장소는 만들지 않는다.
개발 이력은 파생 브랜치에 남기고, 설치 PC에는 Git 전체 복제본 대신 버전 고정 배포물을 전달한다.
로봇 실기 설치·실행은 아직 수행하지 않았으며, 현재 설계가 실행 검증을 뜻하지 않는다.

## 2. 현재 코드에서 확인한 사실

- 우리 HTTP API는 FastAPI 기반 프로세스·설정 관리이다.
  웹의 실제 스케치와 작업 요청은 rosbridge를 통한 ROS 메시지로 전달된다.
- 우리 핵심은 web/, src/sketch_control/, src/rbpodo_painting_control/에 있다.
  세 경로의 현재 추적 파일 합계는 3,119,618 bytes이다. 테스트·기존 보조 코드도 포함한다.
- 전체 main 추적 파일은 322,452,982 bytes이고, rbpodo_ros2/eoat_description/vendor가
  318,442,253 bytes를 차지한다. Git 이력·의존성·빌드 결과는 이 수치에 포함되지 않는다.
- SNUCEM의 평면 후보는 rb20_spray.node_base에서 추출·유지된다.
  후보 status는 ID, 중심, 법선, 지지점 수, 역할 등을 제공하지만
  우리 화면이 요구하는 실제 경계 꼭짓점과 픽셀 경계가 모두 들어 있지는 않다.
  aim_geometry는 유한 면의 기하를 제공하나, 후보 카탈로그 ID와 선택 세대의
  일대일 계약은 별도 연결이 필요하다.
- SNUCEM의 뿜칠 모델은 RB10/RB20 모두 노즐 끝 tcp의 +Z를 분사축으로 쓴다.
  우리 기존 기본값 RB10 -Y를 그대로 가져오면 맞지 않는다.
- SNUCEM 공유제어 실행기는 연속 이동 명령을 처리한다.
  우리 자동 경로 실행기는 MoveIt 계획 및 FollowJointTrajectory 기반으로 동작한다.
  두 실행기는 서로 대체 가능한 동일 인터페이스가 아니다.

## 3. 선택한 구조

기존 ROS 기능을 작은 overlay와 API 서비스로 묶는다.
HTTP/ROS를 모두 새 REST 경로로 다시 작성하지 않는다.

SNUCEM 카메라·평면 추출 -> 평면 연결 계층 -> 우리 웹/선택/경로 생성
우리 자동 실행 계층 -> SNUCEM MoveIt/컨트롤러/드라이버

SNUCEM 로봇 stack, URDF/SRDF, TF, 카메라 설치의 소유권은 SNUCEM에 둔다.
추가 패키지 관리 API는 자신이 시작한 추가 기능만 시작·종료한다.
외부 stack의 준비 상태를 확인하고, 기존 프로세스를 중복 기동하거나 종료하지 않는다.

다른 접근과 비교:
- 저장소 전체 별도 설치: 기존 실행 구조를 유지하기 쉽지만 모델과 빌드가 중복되므로 제외한다.
- 전체 REST 재작성: 내부 API를 통일할 수 있지만 경로 상태·실행기 재작성 범위가 커서 제외한다.
- 선택한 overlay 방식: 기존 웹/경로 자산을 재사용하며 설치물에서 큰 자산을 제외한다.

## 4. 패키지 경계

제안 디렉터리:
- addons/snucem_spray/: 추가 패키지 설정, 진입점, 연결 모듈, 패키지 생성 설정
- scripts/package_snucem_spray.py: 허용 목록 기반 배포물 생성
- docs/SNUCEM_SPRAY_ADDON.md: 새 PC 설치, 상태 확인, 모의 검증, 갱신 안내
- 기존 web/, sketch_control, rbpodo_painting_control: 필요한 구현을 재사용
- 새로운 ROS 독립 단위 테스트와 ROS 연동 검사: 각 계층의 입력/출력 계약 검증

배포물 포함:
- 웹 정적 파일, 관리 API, 설정 예제
- 작업영역/스케치 투영/수동·자동 분사 경로 생성
- 자동 경로 실행과 필요한 공통 경로·공구 처리 코드
- SNUCEM 평면/모델/실행 상태 연결 코드
- 설치·사전 검사·실행 도구와 버전/해시 manifest

배포물 제외:
- .git, 빌드·로그·가상환경·기록 데이터
- 우리 로봇·카메라·EOAT mesh와 vendor 소스
- 우리 base/v0/v1/v2 평면 추출 실행 구성
- Isaac Sim, D405 계측, 롤러 도장·힘제어 실행 구성

기존 혼합 모듈이 경량 공통 Python 함수를 import하는 경우에는 기능을 유지하는 데 필요한
모듈을 포함할 수 있다. 기존 실행기를 무리하게 전부 재작성하지 않는다.
설치 시 이 도장 전용 노드를 시작하거나 해당 하드웨어 의존성을 강제로 추가하지 않는다.

배포 목표는 압축 5 MB 이하, 풀린 자체 파일 10 MB 이하이다.
이는 구현 전 목표이며 설치 의존성 용량을 포함한 보장이 아니다.
최종 결과에는 실제 파일 목록·압축/비압축 크기·추가 의존성을 별도 기록한다.

## 5. 평면 연결 계약

SNUCEM의 추출·분류·유지 알고리즘을 수정하거나 복제하지 않는다.
기존 출력만으로 완전한 계약을 구성할 수 없으므로, add-on에 포함한 exporter wrapper가
설치된 rb20_spray.node.RB20SprayNode를 재사용하고 잠금된 면 목록을 내보낸다.
기존 node 명령을 이 wrapper 진입점으로 대체한다. 두 평면 추출 노드를 동시에 띄우지 않는다.
SNUCEM 소스 파일을 덮어쓰지 않으며 지원 기준 커밋/필수 Python 인터페이스를 검사한다.

exporter가 제공하는 버전 지정 카탈로그:
- schema_version, source_revision, stamp_ns, frame_id, camera/calibration 식별
- plane_id, source, center, normal, 실제 유한 support 경계
- 관측 면/추정 면 구분, 유효성·잠금·제거 상태
- 조각이 떨어져 있거나 경계가 오목하면 실제 영역을 보존한 복수 convex cell

우리 adapter는 카탈로그와 촬영 정보/TF를 받아:
1. 경계를 영상 좌표로 투영하여 웹에 표시한다.
2. 사용자의 대상 선택 요청에 맞는 평면 스냅샷과 generation을 만든다.
3. 기존 /perception/target_planes 및 ZED 선택 계약에 연결한다.
4. 선택한 면이 실제 변경·제거되거나 보정/좌표계가 바뀌면 준비된 경로를 무효화한다.

관측 timestamp만 갱신되었다는 이유로 사용자의 경로를 매번 삭제하지 않는다.
오래된 선택 응답은 적용하지 않는다. 작업영역은 유한 면의 실제 지지 범위를 넘어가지 않는다.
복수 조각 사이 빈 공간을 하나의 볼록 경계로 채우지 않는다.
추정으로 확장된 영역은 자동 작업영역으로 조용히 사용하지 않는다.

## 6. 모델과 자동 실행 연결

실행 중인 SNUCEM /robot_description과 해당 stack의 SRDF·관절 제한을 사용한다.
우리의 다른 URDF, 준비 자세, 충돌 제외 목록을 그대로 주입하지 않는다.
base는 실제 stack의 link0, 도구는 tcp를 기준으로 하고 두 로봇 모두 분사축 +Z를 사용한다.
경로의 로봇 모델·공구 모델/끝점·설정 지문은 검증 및 실행 시 다시 일치시킨다.

노즐 끝이 이미 tcp 원점인 모델에는 기존 끝점 보정을 중복 적용하지 않는다.
EOAT mesh는 설치된 SNUCEM의 로컬 자산 경로를 참조한다.
실제 모델에 공구가 이미 붙어 있으면 같은 충돌 공구를 중복 추가하지 않는다.
공구 프로파일/장착이 달라지면 기존 계획을 재사용하지 않는다.

우리 자동 실행 기능은 기존 경로 생성·계획·검증·중단 로직을 유지하면서
외부 MoveIt 서비스와 joint_trajectory_controller 액션에 연결한다.
실행에 필요한 상태가 기존 환경에 없으면 명시적으로 차단하며,
호환성을 위해 가짜 ready/ack/compliance 상태를 발행하지 않는다.

원격조작과 자동 실행의 소유권은 배타적으로 운영한다.
자동 실행 중 SNUCEM 공유제어 executor가 동시에 명령하면 안 된다.
전환은 이전 명령의 종료·취소를 확인한 뒤 허용하고 연결 해제 시 자동 재개하지 않는다.

물리 분사 밸브 드라이버는 기존 SNUCEM 코드에 포함되지 않는다.
설치/모의 검증/분사 OFF 이동 검증과 실제 분사 허용은 구분한다.
실제 분사는 기존 분사 출력 계약에 맞는 장치 피드백이 있을 때만 허용한다.

## 7. 웹 및 관리 API

기존 UI의 면 선택 -> 작업영역 -> 수동 경로 또는 자동 채우기 -> 검증 -> 작업 시작 흐름을 유지한다.
이 설치 프로필에서는 Spray만 노출하고 Paint/D405/힘제어 설정을 표시하지 않는다.
자체 평면 추출 버전 선택은 노출하지 않고 SNUCEM 평면 공급원을 표시한다.
외부 stack 상태와 추가 기능 상태를 구분하여 표시한다.

FastAPI 관리 API와 rosbridge 메시지를 유지한다.
관리 서버 시작/설정 변경/prepare는 작업 경로 실행을 뜻하지 않는다.
기존 포트 충돌과 ROS domain, 서비스/액션, TF/영상 정보, 모델 준비 상태를 검사한다.
기존 rosbridge를 재사용할 때는 외부 소유로 표시하고 종료 대상으로 삼지 않는다.
기본 API 포트는 8081, 웹 ROS 연결은 구성 가능한 기존 rosbridge 주소를 사용한다.

## 8. 설치·갱신

지원 설치 대상은 기존 저장소와 동일하게 Ubuntu 22.04 x86_64 / ROS 2 Humble / Python 3.10로 둔다.
다른 환경에는 자동 호환을 주장하지 않는다. 새 PC 실환경은 설치 전 검사한다.

1. 사용자가 SNUCEM_Robot_22.04를 설치·빌드하고 카메라/로봇 모델 구성을 완료한다.
2. add-on 배포물과 SHA256 manifest를 가져와 설치된 SNUCEM 경로를 지정한다.
3. installer가 경로·버전·의존성·소스 인터페이스를 검사한다.
4. SNUCEM ROS 환경을 underlay로 사용해 필요한 add-on만 구성한다.
5. 별도 로컬 설정에 IP, domain, 카메라, 모델, 보정/공구 경로를 기록한다.
6. 자체 doctor와 모의 연동 검사를 실행한다.
7. 사용자 지정으로 서비스와 작업을 시작한다.

installer는 rbpodo SDK/vendor를 다시 받지 않고 SNUCEM을 다시 빌드하지 않는다.
비밀·보정값은 배포물에 넣지 않으며 사용자 설정을 갱신 과정에서 덮어쓰지 않는다.
배포 버전마다 별도 디렉터리를 사용하고 중지 상태에서만 활성 버전을 바꾸어 복구 가능하게 한다.
전체 Git clone이 설치의 선행 조건이어서는 안 된다.

## 9. 검증 및 완료 기준

- 합성 평면: ID/좌표/단위/법선, 분리된 영역, 좁은 플랜지, 영상 밖/TF 누락 처리.
- 평면 교체/삭제/보정 변경: 예전 요청·경로 거절, timestamp만 바뀐 경우 선택 유지.
- 모델: RB10/RB20 +Z, 노즐 끝점 중복 보정 방지, SRDF/관절/공구 불일치 차단.
- 웹: 기존 수동·자동 경로 및 작업영역 회귀 검사, Spray 전용 흐름.
- 실행: 외부 MoveIt 액션 계약, 준비 실패, 취소, 통신 끊김, 동시 원격조작 차단.
- 배포: archive 파일 검사, 큰 모델/vendor/.git 제외, 임시 경로 설치 및 재설치 검사,
  기존 SNUCEM 파일과 로컬 설정 무변경.
- Linux ROS fake 환경: 외부 stack 연결 -> 영상/평면 -> 스케치 -> 계획 -> 모의 실행/취소.
- 실제 로봇·카메라와 물리 분사는 단위 테스트 통과로 성공을 주장하지 않는다.

Windows 개발 환경에서 가능한 순수 Python/웹/패키징 검증과
Ubuntu ROS 환경에서만 가능한 실행 검증을 결과에 명확하게 구분한다.
필요한 실환경이 없으면 미검증 항목을 명시하고 실제 사용 가능 판정을 보류한다.
