# 기존 스케치 UI의 용접 설정과 Isaac 용접심 추종 설계

## 목적과 합의된 범위

ZED 영상에서 작업대상을 지정하고, 외부에서 받은 3D 용접심 중 여러 개를 선택한 뒤, 토치 자세와 위빙 조건을 적용해 Isaac Sim의 EOAT를 움직인다. 2026-10-13 대화에서 사용자는 이 방향을 승인했고 다음 사항을 추가했다.

- 공식 Michelo·Outpost 및 minjeasung 스케치 UI를 그대로 활용한다.
- 작업대상 스케치는 ZED 영상 위에서 한다. 스케치를 용접 경로로 사용하지 않는다.
- 추출 알고리즘은 개발 중이며 용접심을 3D 좌표로 제공할 예정이다.
- 3D 용접심을 ZED 영상에 겹치는 기능은 이번 구현에서 제외해도 된다. 용접심 추종과 적절한 토치 각도 유지가 우선이다.
- 기존 스케치 UI에 Settings 패널을 추가한다. 용접뿐 아니라 도장·뿜칠에서도 사용할 공통 패널이다.

이 문서는 구현할 동작과 인터페이스를 정의한다. 알고리즘의 출력 형식이나 실제 용접기 규격이 이미 확정되었다는 뜻은 아니다. 아래 내부 계약으로 외부 출력을 변환하는 어댑터를 연결한다.

## 현재 코드와 변경 경계

`web/index.html`은 ZED 캔버스, 대상/작업영역/경로 단계, 오른쪽 작업 패널, 실행·중단 버튼을 제공한다. `web/js/app.js`와 `plane_workflow.js`가 도장과 뿜칠의 상태 및 선택을 처리한다. 별도 용접 웹 앱이나 대체 Michelo 화면을 만들지 않는다.

현재 `robot_models.py`는 paint/spray만 허용한다. `process_supervisor.py`와 Construct 실행 스크립트는 isaac_construct를 spray에 고정한다. 이 연결에 weld 공정을 추가하되 실행 환경과 공정을 별도로 취급한다. 기존 paint/spray 설정은 유지한다.

공식 서비스 → 기존 Outpost ROS 브리지 → 기존 스케치 UI의 ZED 영상 경로를 사용한다. 새로운 카메라 서버나 별도 카메라 소유자를 추가하지 않는다. `weld_visualizer.py`의 표면 근접 비드 표시는 실제 용접 실행 판정으로 재사용하지 않는다.

현재 작업 트리의 Construct 및 다른 미커밋 변경은 구현의 기반으로 보존한다. 이번 설계 커밋에는 이 문서만 포함한다.

## UI와 사용자 작업 흐름

기존 페이지의 브랜드, 캔버스, 스타일, 연결 상태, 작업 시작·중단 버튼을 유지한다. 공정별 단계 안내와 오른쪽 패널 내용만 확장한다.

1. 작업관리에서 Isaac Construct와 사용할 팔을 선택하고 공정을 용접으로 설정한다. 한 번에 한 팔만 실행한다.
2. 기존 ZED 화면에서 작업대상을 둘러 표시한다. 용접 모드에서는 닫힌 영역 또는 사각형을 사용하며 열린 선은 대상 확정 안내를 표시한다.
3. 대상 확정 후 용접심 입력을 요청한다. 1차 구현의 제공자는 해당 시험 작업물에 등록한 용접심을 반환한다.
4. 오른쪽 목록에서 용접심 ID, 길이, 좌표계, 자세 준비 상태를 보고 여러 개를 선택한다. 선택 순서를 실행 순서로 사용하며 순서 변경과 진행 방향 반전을 지원한다.
5. Settings 패널에서 조건을 적용하고 경로 검증을 요청한다. Isaac 장면에서 선택한 중심 경로, 계획된 위빙 경로, 토치 방향을 확인한다.
6. 검증된 계획을 기존 작업 시작 버튼으로 실행한다. 현재 심, 접근/용접/이탈 단계, 완료·실패·중단 상태를 같은 화면에서 확인한다.

ZED 영상 위에 용접심 선을 표시하지 않아도 이 흐름이 완결되어야 한다. 3D 표시에는 목록과 같은 ID·선택 색을 사용한다. 경로 표시는 로봇을 움직이지 않는다.

시험 제공자는 스케치 픽셀로부터 심을 생성하거나 스케치 영역과 심의 정확한 포함 관계를 추론하지 않는다. 시험 작업물과 대상 요청을 명시적으로 연결하고 화면에 “시험 작업물에 등록된 용접심”이라고 표시한다. 실제 추출기는 대상 영역을 해석해 같은 결과 계약으로 반환한다.

## 공통 Settings 패널

기존 오른쪽 작업 패널에 접고 펼칠 수 있는 Settings 영역을 추가한다. 새 페이지나 별도 설정 앱을 만들지 않는다. 공통 컨테이너와 공정별 설정 모듈로 구성하며, active process가 해당 모듈을 선택한다.

공통 동작은 입력 단위 표시, 형식·범위 검사, 변경됨/적용됨 상태, 적용 버튼, 서버의 확정값 표시, 실행 중 수정 차단이다. 브라우저 입력만 바꾸고 적용된 것으로 표시하지 않는다. 서버가 검증·확정한 설정 revision을 경로 계획에 연결한다.

- 용접: 진행 속도, 접근·이탈 거리, TCP 이격, 기준 자세 프로파일, 작업각·진행각 보정, 위빙 사용 여부·폭·주파수·좌우 정지시간, 전류 설정.
- 도장: 기존 서버가 실제로 지원하는 설정과 현재값을 같은 패널에 연결한다. 편집 API가 없는 항목은 현재값과 실행 설정에서 변경한다는 안내를 표시한다.
- 뿜칠: 기존 속도·이격·도포 폭·겹침 등 지원 설정을 같은 원칙으로 표시한다. read-only launch 파라미터를 브라우저에서 변경 가능한 것처럼 만들지 않는다.

첫 범위에서 도장·뿜칠의 새로운 실행 중 설정 API를 만들지는 않는다. 두 공정에서도 Settings 패널을 열고 유효한 현재 설정을 확인할 수 있어야 한다. 공정별 draft는 분리하며 용접 설정이 다른 공정에 적용되지 않는다. 프로세스 재시작 후에는 서버 설정을 다시 읽고 자동으로 예전 draft를 적용하지 않는다.

위빙 폭은 좌우 끝 사이의 전체 폭(mm), 주파수는 완전한 좌우 왕복의 횟수(Hz), 정지시간은 각 끝에서 머무는 시간(s)으로 정의한다. 로봇 좌표는 내부에서 m/rad/s로 계산하고 UI의 mm/deg 값은 경계에서 한 번 변환한다. 임의의 전류를 실제 용접 추천값으로 제시하지 않는다. 시뮬레이션 시험값은 시험용으로 표시한다.

## 3D 용접심 입력 계약

ROS와 독립적인 데이터 모델과 검증 함수를 먼저 두고 기존 ROS/rosbridge 연결에 전달 어댑터를 붙인다. 버전 1의 논리 계약은 다음과 같다.

| 데이터 | 필수 내용 |
|---|---|
| 대상 요청 | request_id, target_revision, ZED stream generation, image stamp와 해상도, 원본 픽셀 좌표의 대상 polygon, fixture/external 제공자 구분 |
| 추출 결과 | schema_version, request_id, target_revision, generation, source, frame_id, length_unit=m, 획득 시각과 clock domain, seams, 오류 상태 |
| 용접심 | generation 안에서 고유한 seam_id, 순서 있는 points_xyz; 자세 정보로 각 점의 기준 quaternion, reference_up_vectors 또는 자세 프로파일 ID를 선택적으로 포함 |
| 선택 | generation, 순서 있는 seam_id 배열, 각 심의 reverse 여부, selection_revision |
| 적용 조건 | settings_revision, 용접 조건, tool_profile_id와 revision |
| 계획 | plan_id, 입력 revision 묶음, 로봇/팔 식별, 시작 관절 상태, 장면 revision, 구간별 시간·궤적, 검증 결과 |

3D 점열만 있는 결과도 목록에 표시하고 선택할 수 있다. 실행하려면 결과의 자세 정보 또는 명시적으로 선택한 자세 프로파일이 있어야 한다. 프로파일은 시험 작업물의 기준 방향과 도구 축을 제공한다. 위치 점열만 보고 이음부 법선이나 올바른 작업각을 추측하지 않는다.

frame_id는 ROS TF에서 실행 기준 좌표계로 변환 가능해야 한다. 광학 카메라 좌표계와 ZED 본체 좌표계를 구분한다. 변환과 필요한 보정이 없으면 실행 계획을 거부한다. 광학 좌표의 3D 점을 깊이 영상에서 다시 추정하지 않는다.

유효하지 않은 단위, NaN/Infinity, 점 부족, 중복 ID, 길이 0, 불연속 점열, 유효하지 않은 quaternion·방향 벡터, 오래된 대상 요청의 응답은 명시적인 오류로 처리한다. 빈 결과는 “용접심 없음”으로 표시하며 자동 시험 데이터로 대체하지 않는다. fixture 제공자는 명시적으로 선택한 Isaac 시험 모드에서만 사용한다.

## 카메라와 시간 처리

대상 확정에 사용한 ZED 프레임의 식별정보를 요청에 보존한다. 현재 브라우저 압축 이미지 경로에서 누락되는 메시지 식별정보가 있다면 기존 구독 헬퍼를 확장해 함께 전달한다. 실제 3D 결과의 시각과 좌표계는 제공자 계약으로 검증한다.

현재 Construct 브리지는 Outpost 벽시계와 Isaac 시계가 정확하게 동기화된 촬영 시각을 제공하지 않는다. 이를 정밀 동기화로 취급하지 않는다. 1차 시험은 고정 작업물과 정지한 카메라 헤드에서 수행하고, fixture는 장면 좌표계의 알려진 3D 데이터를 사용한다. 헤드 이동, 스트림 generation 변경, 장면 재설정은 대상·선택·계획을 무효화한다.

## 토치 자세와 위빙 경로

각 심의 진행 방향과 기준 방향으로 일관된 국소 좌표계를 구성한다. 인접 점 간 진행 방향이 퇴화하거나 기준 방향과 평행해서 자세를 결정할 수 없으면 계획을 거부한다. 결과 quaternion이 있으면 이를 기준 자세로 사용하며 보간 중 quaternion 부호 차이로 인한 회전을 방지한다. 점별 기준 방향이 있는 경우 연속적인 축과 자세를 생성한다.

작업각과 진행각은 프로파일에서 정의한 이음부 국소 축에 대한 보정이다. UI에 그 기준을 표시한다. 진행 방향을 반전하면 진행각과 좌우 위빙 방향을 반전된 경로 기준으로 다시 계산한다. 급격한 모서리나 자세 변화는 검증 없이 부드럽게 덮어쓰지 않고 심 분할 또는 입력 수정이 필요하다고 표시한다.

토치 끝과 로봇 제어 TCP의 강체 변환, 유효한 도구 축, 충돌 형상, 팔 그룹과 컨트롤러를 선택된 EOAT 프로파일로 명시한다. 기존 spray 축·이격을 용접에 그대로 적용하지 않는다. 기존 Construct 장착물은 용접 토치로 확인된 것으로 취급하지 않는다. Isaac 시험용 토치 형상과 TCP를 별도 프로파일로 명시하고, Isaac과 MoveIt이 같은 장착 변환·충돌 형상을 사용하게 한다.

위빙은 심의 국소 횡방향으로 중심선에서 벗어나는 경로다. 첫 패턴은 부드러운 왕복 패턴 하나와 OFF를 제공한다. 좌우 끝 정지를 포함한 전체 왕복 시간이 1/frequency이며 정지시간 합이 이보다 크거나 같으면 거부한다. 이동 구간은 끝에서 횡속도가 0이 되는 연속 곡선으로 만들고, 시작·종료 시에는 진폭을 점진적으로 연결해 횡방향 위치가 튀지 않게 한다.

진행 속도는 중심선상의 이동 속도로 정의한다. 좌우 정지는 횡방향 정지이며 중심선 전진은 계속한다. 도구 자세는 중심 용접심과 기준 방향을 따르며 위빙 접선 때문에 불필요하게 흔들리지 않는다. 모든 위빙점에 도구 변환과 자세 조건을 적용한다.

MoveIt의 시간 재계산이 위빙 주파수·속도를 바꿀 수 있으므로 최종 궤적 시간으로 두 조건을 재검사한다. 요청값을 유지할 수 없으면 자동 감속 후 동일한 조건이라고 표시하지 않고 설정 변경을 요구한다. 시험 프로파일은 속도·주파수 오차의 허용치를 명시하며 요청 대비 5% 이내를 초기 시뮬레이션 검증 기준으로 사용한다.

## 공통 실행과 Isaac 어댑터

용접 작업 상태는 EMPTY → TARGET_READY → SEAMS_READY → SELECTED → PLANNING → READY → RUNNING → COMPLETED로 진행한다. 실패와 중단은 별도 종결 상태로 표시하고 재실행에는 새 검증을 요구한다. RUNNING에는 APPROACH, WELD, RETRACT, TRANSFER 구간이 있다.

기존 executor의 MoveIt·팔별 컨트롤러 연결과 작업 중단 흐름을 재사용한다. 용접 계약·경로 생성·상태는 작은 전용 모듈로 분리하고 거대한 moveit_executor.py에 모든 수학과 상태를 추가하지 않는다. paint/spray의 표면 승인·접촉력·분사 조건을 weld가 잘못 통과하거나 요구하지 않도록 공정별 실행 조건을 명시한다.

각 심마다 접근 → 시작점 진입 → 위빙 추종 → 이탈을 계획한다. 심 사이 이동도 충돌 검사에 포함한다. 전체 작업을 검증한 뒤 실행하며, 부분 Cartesian 결과를 완전한 계획으로 취급하지 않는다. 기존 충돌 형상을 끄거나 작업물 전체 충돌을 무시해서 경로를 통과시키지 않는다.

설정·선택·자세 프로파일·대상·장면·로봇 모델이 바뀌거나 계획 시작 상태와 실제 상태가 맞지 않으면 실행을 거부한다. 실행 요청에는 plan_id를 포함하고 중복 요청은 새 동작을 시작하지 않는다. 변경 요청은 실행 중 거부한다. 중단은 진행 중 controller action을 취소하고 가상 용접 상태를 OFF로 전환한다. 중단된 계획을 자동 재개하지 않는다.

공정 출력은 configure(settings), start_segment, stop_segment, status라는 공통 어댑터 계약으로 분리한다. Isaac 어댑터는 용접 구간 상태와 설정값을 기록·표시한다. 접근·이탈·심 사이 이동·실패·중단에서는 OFF다. 정상 feedback 없이 마지막 ON 표시가 남지 않도록 수명과 연결 상태를 처리한다.

1차 구현은 실제 용접기 드라이버나 물리적인 아크·열·용입 시뮬레이션을 포함하지 않는다. 실제 출력 어댑터가 없는 실장비 weld 실행은 구체적인 미지원 사유로 거부한다. 향후 실장비에서 같은 작업 코드를 사용하려면 해당 로봇·토치 프로파일과 용접기 드라이버를 연결해야 한다.

## 시험 데이터와 검증 기준

시험 심은 기존 `scripts/construct_scene_objects.py`의 작업물 형상에 맞춰 정의하고 장면 revision과 연결한다. 도달 가능성과 ZED에서 지정할 대상의 가시성은 실제 Isaac 실행으로 확인한다. 검증을 위해 작업물이나 팔 초기 자세 조정이 필요하면 시험 프로파일에 명시하고 실행 때 몰래 장면을 이동하지 않는다.

선택/제외/순서 검증을 위해 최소 세 심을 제공하고 두 심을 선택해 실행한다. 직선과 완만한 곡선의 자세 처리도 검증하되, 합성 곡선은 실제 이음부라고 표시하지 않고 기하 시험 경로로 구분한다.

| 검증 계층 | 완료 증거 |
|---|---|
| 데이터·기하 | 3D 좌표와 단위, TF 변환, 역방향, 도구 변환, 자세 연속성, 위빙 폭·시간, 퇴화 입력 거부를 검사하는 단위 테스트 |
| 상태·설정 | 오래된 응답, 설정 revision 불일치, 미확정 자세, plan 변경, 중복 실행, 중단, 실장비 미지원 거부 테스트 |
| 기존 UI | 같은 스케치 페이지에서 ZED 대상 지정·목록 선택·Settings 적용·시작/중단이 동작하고 paint/spray 회귀 테스트가 통과함 |
| Isaac 통합 | 공식 카메라 경로, 세 심 중 두 심 선택, 조건 적용, 검증된 궤적 실행, 실제 joint/TCP feedback 기록 |
| 자세·위빙 | 계획 대비 실제 TCP 위치·자세 오차, 중심선 대비 위빙 폭, 시간당 위빙 주파수를 측정함 |
| 중단·실패 | 이동 중 중단, 도달 불가능한 심, 잘못된 좌표계, 장면 reset 후 실행 거부를 재현함 |

위치 오차 5 mm, 자세 오차 5 deg 이내를 초기 시뮬레이션 추종의 통과 기준으로 사용하며 실용접 정확도 기준으로 주장하지 않는다. 보고서는 요청 조건, 계획 결과, 실제 feedback을 구분하고 최댓값을 포함한다. 계획 궤적만 계산하거나 UI 테스트만 통과한 상태를 Isaac 이동 검증 완료로 표시하지 않는다.

## 범위 밖과 다음 연결점

이번 범위 밖은 실제 용접심 검출·실시간 재추적 알고리즘, ZED 영상의 3D 심 오버레이, 실제 용접 전원 통신, 용융·열변형 물리, 여러 팔 동시 용접, 도장·뿜칠의 새로운 실행 중 설정 API다.

추출기 연결 시에는 frame_id·단위·시각·심 ID를 내부 계약으로 변환한다. 자세 정보가 없는 추출 결과에는 명시적인 작업물/토치 자세 프로파일을 결합한다. 실장비 연결 시에는 공통 작업 로직을 유지하고 실제 입출력과 보정·도구 프로파일을 검증한다.
