# 다중 평면 선택과 내화뿜칠

## ZED 전용 뿜칠: 9단계 흐름

1. 전체 종료 상태에서 공정을 **Spray**로 선택한다. API 설정은 `process_mode=spray`,
   직접 launch는 `process_mode:=spray`이다. 기본 `work` 공정은 Paint이며,
   `spray_motion_test` 프로필은 Spray로 시작하고 분사는 항상 OFF이다.
2. 선택한 로봇 모델, ZED RGB·깊이·카메라 정보, 장치 ID·시리얼, IPC 및 ZED→로봇 TF를 확인한다.
   Spray 시작은 D405 브리지·드라이버·refiner·perception TF를 띄우지 않는다.
3. ZED 영상에서 대상 외곽을 그린다. 추출 범위와 실제 깊이 지지점이 물체를 포함하는지 확인한다.
4. 평면을 추출하고 필요한 면을 선택한다. 법선은 면에서 카메라/자유 공간 쪽으로 나오는 방향이다.
5. ZED 측정으로 선택 면을 확정한다. D405 접근·촬영·근접 보정 이동은 수행하지 않는다.
   최신 `/perception/zed_target_lock`과 `/perception/zed_surface_status`가 일치해야 한다.
6. 작업할 면을 활성화하고 ZED 정면 투영 화면과 면 경계를 확인한다. 다른 면으로 바꾸면
   이전 면의 작업영역·경로를 재사용하지 않는다.
7. 활성 면 안에 사각형, 자유선 또는 이어진 직선으로 작업영역을 둘러 그리고 **작업영역 확정**을 누른다.
   직선은 시작점·끝점을 두 번 클릭하고 다음 선을 이전 끝점에 이어 그린다. 자유선은 드래그한다.
   마지막 점과 첫 점은 자동으로 연결한다. 직선 하나는 면적이 없으므로 작업영역이 될 수 없다.
   선이 교차하는 영역은 거절된다. ZED 기준의 평면·영역 검증 결과를 확인한다.
   UI는 아래 Spray 전용 작업영역 요청과 같은 좌표·stamp의 `/work_area_pixels`를 함께 보낸다.
8. **경로·실행**에서 **자동 도포 경로 생성**을 누르거나, 직선·자유선으로 원하는 경로를 그린 뒤
   **그린 경로 사용**을 누른다. 자동 채우기는 실제 작업영역 경계에 맞게 잘라 생성하며,
   수동 경로는 선 중간까지 영역 안에 있어야 한다. 여러 선 사이 이동에서는 분사를 끈다.
   노즐 이격 0.500 m, 분사 폭 0.350 m, 겹침 30%, 속도 0.020 m/s
   및 모델별 공구 축을 미리보기에서 확인한다.
9. 충돌 없는 MoveIt 계획과 실행 준비 상태를 확인하고 명시적으로 작업 시작을 승인한다.
   완료 후 다음 면은 활성화·영역 지정·경로 생성부터 다시 수행한다. 자동 다중 면 실행 큐는 없다.

처음부터 Spray로 시작한 실행기는 Paint 전환을 거부한다. Paint가 필요하면 전체 종료 후
`process_mode=paint`로 다시 시작하여 D405와 보정을 준비한다. 라이브 모드 요청은 기존
`/painting_system/set_process_mode`, 확정 상태는 `/painting_system/process_mode`를 사용한다.
시작 설정은 프로세스 구성을 결정하며 라이브 토픽만으로 D405 프로세스를 만들지 않는다.

## Spray 작업영역 입력 계약

projector의 Spray 전용 입력은 `/painting_system/zed_work_area_request`이다.
메시지 형식은 `std_msgs/String`이며 `data`에 다음 JSON 객체를 직렬화하여 넣는다.

```json
{
  "source": "zed",
  "plane_generation_id": "<current zed_target_lock.plane_generation_id>",
  "header": {
    "frame_id": "wall_front",
    "stamp": {"sec": 1780000000, "nanosec": 123000000}
  },
  "pixels": [[100, 100], [300, 100], [300, 250], [100, 250]]
}
```

예시의 `plane_generation_id`는 현재 `/perception/zed_target_lock`에서 받은 값을 그대로
사용한다. `source`는 `zed`, `header.frame_id`는 `wall_front`이고, `pixels`는 해당 정면
투영 화면의 `[u, v]` 픽셀 좌표 배열이다. 명시적인 평면 세대로 작업영역 요청을 현재 대상에
묶으므로 이전 대상에서 보낸 요청을 새 대상의 기하로 해석하지 않는다.
사각형과 다각형 경계를 지원하며, 영역 상태의 `boundary_pixels`에 검증된 경계를 보존한다.
`corners`는 기존 정면 좌표 변환을 위한 외접 사각형이고 경로의 허용 범위는 실제 경계로 검사한다.
수동 뿜칠 경로는 `/painting_system/zed_sketch_request` (`std_msgs/String`)로 보내며,
`source=zed`, `plane_generation_id`, `work_area_id`, `selection_id`, Wall Front `header`,
선별 픽셀 배열 `strokes`를 함께 전달한다. 현재 선택과 다른 요청이나 같은 선택의 오래된 요청은 무시한다.
선택 식별이 없는 `/sketch_pixels`는 뿜칠에서 거절하고 롤러 도장의 기존 입력으로 유지한다.
생성된 계획의 `source.coverage`는 `manual_sketch`이다.
자동 채우기는 기존 `auto_fill` 값을 유지한다. 전송은 경로 생성 요청이며 로봇 동작은
검증 후 **작업 시작**을 눌러야 한다. ZED 전용 미리보기 모드에서는 로봇 실행을 허용하지 않는다.

UI는 같은 선택에 대해 `/work_area_pixels` (`geometry_msgs/PoseArray`)도 발행한다.
두 메시지는 동일한 `header.frame_id`, 동일한 `header.stamp.sec/nanosec`, 동일한 순서의
픽셀 좌표를 사용한다. PoseArray의 각 `pose.position.x/y`는 JSON의 `u/v`에 대응한다.
두 발행에 stamp를 따로 생성하지 않는다. generator와 executor는 이 메시지 쌍의 선택 식별과
`/perception/zed_surface_status`의 `selection_id` 및 `plane_generation_id`를 맞춰 검증한다.

이 stamp는 메시지 쌍을 식별하는 값이다. projector는 브라우저 `Date.now()`와 ROS clock을
비교하여 요청이 대상 잠금 이후인지 판정하지 않는다. 대상 연결은 envelope의 명시적인
`plane_generation_id`로 확인한다. Spray의 projector는 이 전용 envelope만 작업영역 기하
입력으로 받으며, 기존 `/work_area_pixels` 단독 메시지는 Spray 기하를 정의할 수 없다.
기존 generic 픽셀 입력에 의한 projector 작업영역 정의는 Paint 흐름에 해당한다.

## 도장 흐름

1. 기존 `rb10_painting_system.launch.py`를 실행하고 웹 UI를 새로고침한다.
2. **대상 선택** 단계에서 대상을 둘러 그린 뒤 **평면 추출**을 누른다. 닫힌 자유곡선·사각형 내부만 추출 대상으로 사용한다. 두 점의 직선 입력은 사각형으로 해석한다.
3. 색상 윤곽과 번호로 표시되는 후보 중 필요한 면을 체크하고 **선택한 면 측정**을 누른다.
4. 현재 관절 상태에서 충돌 없는 IK의 관절 변화량이 작은 면부터 하나씩 접근·정지·측정한다. 매 측정 후 남은 면의 순서를 다시 계산한다. 실패한 면은 임의로 통과하지 않는다. 성공 결과는 면별로 보관한다. 마지막으로 측정한 면의 정면 화면에서 시작한다.
5. 다른 면은 **작업할 평면**에서 선택한다. D405가 그 면으로 다시 접근하고 측정한 후 작업영역을 그린다. 이전 면의 작업영역·경로는 재사용하지 않는다.
6. 작업영역 설정 및 기존 D405 작업영역 보정 후 롤러 도장 경로를 직접 그리거나 **영역 자동 채우기**를 사용한다. 공정 변경 시 경로를 다시 생성한다.
7. 작업영역과 경로 검증 상태를 확인하고 **작업 시작**을 누른다. 면별로 작업영역과 경로를 생성·실행한다. 선택한 모든 면의 도포 작업을 한 번에 자동 실행하는 배치 큐는 포함하지 않는다.

## 평면 및 자세

스케치 내부 깊이 점에 RANSAC을 적용하고 해당 inlier를 제거한 뒤 다음 면을 추출한다. 기본 상한은 8개, 최소 80점, 거리 임계값 15 mm이다. 면 ID에는 추출 요청의 세대 ID가 포함된다. 선택하지 않은 검출 면도 충돌 객체로 유지한다. 검출 윤곽은 inlier 픽셀의 볼록 껍질이며 실제 경계 전체를 보장하지 않는다.

Paint에서는 D405가 선택된 각 면의 법선을 기준으로 정밀 측정한다. Spray에서는 ZED의 대상 잠금과 표면 상태가 기준이다. 측정 결과의 대상·평면 세대를 검증하여 이전 면의 결과를 다음 면으로 오인하지 않도록 한다. 노드 재시작 후에는 다시 추출·측정한다.

Paint는 기존 TCP +Y 법선 정렬을 유지한다. Spray는 선택한 공구의 분사 축을
**바깥쪽 면 법선의 반대 방향(-normal)** 으로 정렬한다. `spray_tool_axis=""`는
`model_id`에 따라 RB10 `-y`, RB20 `+z`를 자동 선택한다. 축은 application TCP 좌표계
기준이므로 flange의 같은 이름 축과 혼동하지 않는다. 왕복 시 180도 자세 뒤집힘을 피한다.

## Paint의 D405 측정 이동 최소화

- 장착 방향을 TCP −Y로 가정하지 않고 `tcp → d405_color_optical_frame`의 실제 TF를 사용한다.
  측정 광축 +Z가 선택 면을 향하도록 자세를 계산하고, **광학 중심**을 평면에서 법선 방향 0.32 m에 둔다.
  카메라 TF가 없으면 측정 접근을 진행하지 않는다. 도포 중 롤러/뿜칠 자세 규칙은 별도로 유지한다.
- ZED 평면 inlier의 평면상 볼록 윤곽 내부에서 가장 가까운 지점, 중앙과의 중간 지점, 중앙을
  최대 3개 후보로 만든다. 가장자리 여유 80 mm를 확보할 수 없는 작은 면은 거부한다.
  각 지점에 광축을 유지하는 두 roll 자세를 만들고 동일한 실측 관절 상태로 충돌 검사 IK를 수행한다.
- IK 관절 변화량이 작은 순서로 MoveIt 경로를 계획한다. 최대 3개의 유효한 전체 경로를 비교해
  누적 관절 이동량이 가장 작은 경로를 실행한다. 비교 후에도 장면 세대와 실측 시작 관절을 재검사한다.
  후보 전체에 대한 전역 최적해나 최단 작업 시간 보장은 아니다.
- 이미 목표 자세에서 2 mm/1° 이내이고 실측 관절 도착·정지 조건을 만족하면 이동 명령을 생략한다.
  이때도 충돌 검사 IK/경로와 도착·정지 검증을 거친 뒤 안정화 시간을 두고 촬영한다.
- 여러 면의 순서는 각 면의 최대 3개 내부 측정점·두 roll 자세의 collision-aware IK로 비교한다.
  가까운 지점의 IK가 실패해도 중앙 쪽 후보를 확인한 뒤 도달 가능 여부를 판단한다.
  최대 관절 변화량, L2 변화량, 총 변화량 순으로 고른다. 전체 면의 경로를 미리 전부 계획하는 방식은 아니다.
  마지막으로 실제 측정한 면을 활성화하므로 클릭 순서의 마지막 면으로 불필요하게 돌아가지 않는다.
- `/d405/refine_target_request` (`std_msgs/String`, JSON)는 `target_stamp`, `frame_id`,
  `sample`, `support_polygon`을 한 메시지로 전달한다. 실제 도착 광축과 평면의 교점을 사용하고,
  촬영 직전 이격 0.32±0.015 m, 광축 정렬 3° 이내, 윤곽 가장자리 여유 최소 75 mm를 확인한다.
  refiner는 요청의 평면 식별과 범위를 검증한 뒤 한 프레임만 사용한다.
- 점군 ROI는 해당 측정점으로 옮기고 선택 면의 윤곽 내부로 제한한다. 기존 RANSAC/오차/지지점
  품질 기준은 완화하지 않는다. 거절 시 다른 측정점에서 다시 시도하며 실패를 성공으로 처리하지 않는다.
- 볼록 윤곽은 가림이나 구멍을 완전히 표현하지 못한다. 현장에서 충분한 깊이 지지점과
  주변 물체의 충돌 모델을 확인해야 한다. 근접 관절 해 선택과 실제 이동 거리 감소는 실기 검증 대상이다.

## 도장과 뿜칠

- 도장: 기존 접촉 탐색, 힘 증가/감소, 20–30 N 힘 밴드, 획 사이 10 mm 후퇴, 마지막 80 mm 후퇴를 유지한다. 기존 롤러 토크 제어 기본 OFF 설정도 유지한다.
- 뿜칠: 바깥쪽 법선 방향으로 **확인된 EOAT 노즐 끝점에서 표면까지 기본 0.500 m** 이격한다. 롤러 반지름이나 접촉 기하 오프셋 0.026 m를 더하지 않는다. [EOAT 프로파일](SPRAY_EOAT_PROFILE.md)의 mesh 단위·장착 변환·실제 노즐 끝점을 실측하고 확인해야 한다. 빈 경로, 누락 또는 미확인 프로파일은 Spray 생성·실행을 차단한다. 실제 장비 mesh는 제공하지 않으며, 충돌 검사는 마운트와 가드를 포함한 전체 변환 mesh를 사용한다.
- 뿜칠 도포 구간은 `SPRAY`, 획 사이 이동은 `SPRAY_TRAVEL`이다. 획 사이 추가 후퇴 없이 동일 이격면에서 이동한다. 시작/종료/접근/이동/계획 대기에서는 OFF이다.
- 뿜칠 자동 채우기는 350 mm 폭, 30% 겹침으로 기본 행 간격 245 mm를 사용한다. 도포 경로 속도는 20 mm/s, OFF 이동은 30 mm/s이다. 도장 롤러의 175 mm 폭 설정과 분리되어 있다. 실제 뿜칠 폭·분사량·밸브 지연에 대한 공정 보정은 현장 검증 대상이다.
- 작업영역의 좌우 폭이 설정된 분사 폭 이하이면 중앙에 세로 경로 1줄을 생성한다. 분사 폭 자체를 줄이지 않으므로 좁은 영역에서는 분사 범위가 좌우 경계를 넘어간다. 넓은 영역은 기존 겹침 간격으로 채우고, 롤러 도장의 폭 제한은 그대로 유지한다.
- 뿜칠 모드에서는 힘 요청과 compliance를 OFF로 고정하고, F/T tare·접촉 탐색·힘/토크 보정을 사용하지 않는다. 반력과 F/T 유효성만으로 경로를 정지시키지 않는다. 컨트롤러 오류, 충돌 검사, 로봇 자체 인터록, 비상정지와 뿜칠 장치 통신 감시는 유지한다.
- 계획은 기존 v3 해시/작업영역/평면 세대 검증을 사용하며 `process_mode`도 해시에 포함된다. 도장과 뿜칠의 행을 혼합한 계획은 거부한다.

## 뿜칠 파라미터와 현장 검증

| 파라미터 | 기본값 | 적용 |
|---|---|---|
| `process_mode` | `paint` | executor, projector, generator, D405 refiner의 시작 공정 |
| `model_id` | `rb10_1300e_u` | 로봇 모델 및 공구 축 선택 |
| `spray_tool_axis` | 빈 문자열 | RB10 `-y`, RB20 `+z`; executor와 generator에 동일하게 전달 |
| `spray_eoat_profile` | 빈 문자열 | Read-only JSON path shared by generator/executor; empty blocks Spray. See [EOAT profile](SPRAY_EOAT_PROFILE.md). |
| `spray_footprint_width_m` | `0.35` | generator의 분사 폭 |

통합 launch, real/perception launch, `core`, `sketch_control`, `phase1_python`,
`phase2_unity`에 공정과 공구 축/경로 파라미터를 전달한다. Phase 계열은 기존 UR10
시뮬레이션 bringup을 유지하므로 RB10/RB20 실장비에는 `rb10_painting_system.launch.py`를 사용한다.
설정을 변경하면 이전 경로를 폐기하고 다시 생성·검증한다.

ZED 깊이 정확도, 보정 TF, 대상 경계와 법선 부호, 실제 노즐 기준점 및 분사 축,
0.500 m 이격의 실측값, 실측 분사 폭·겹침·속도·도포량, 충돌 모델과 관절 여유를
확인해야 한다. RB20 Spray는 모델별 ZED 보정만 필요하고 D405 보정 파일은 요구하지 않는다.
RB20 Paint는 두 보정 모두 필요하다. ZED 데이터·TF가 없거나 오래되면 실행을 승인하지 않는다.
`spray_motion_test`는 건 없는 이동 확인용이며 실제 밸브와 분사 품질은 검증하지 않는다.
실제 분사는 아래 어댑터 계약, 물리적 OFF 동작과 비상정지까지 별도로 검증해야 한다.

## 뿜칠 장치 ROS 계약

아직 실제 밸브/PLC/디지털 출력 어댑터는 연결하지 않았다. 실제 실행은 장치의 최신 OFF 확인과 compliance OFF 상태가 없으면 거부한다. dry-run은 실제 로봇 궤적과 gun ON을 내보내지 않는다.

뿜칠건이 없는 현재 EOAT로 실제 경로 이동만 검증할 때는 별도 `spray_motion_test`
프로필을 사용한다. 시작 시 고정되는 이 모드에서는 건 응답을 요구하지 않으며,
출력 명령은 항상 OFF이고 도장 모드 전환도 거부한다. 실제 건의 상태를 확인했다고
간주하거나 모의 ACK를 발행하지 않는다. 최신 compliance OFF, 힘 명령 OFF,
충돌·계획·로봇 인터록은 유지한다. [검증 절차](SPRAY_MOTION_TEST.md).

`/spray_gun/command` (`std_msgs/String`, JSON, 20 Hz):

```json
{"session_id":"UUID","command_id":1,"on":false,"lease_ms":250,"path_id":"...","process_mode":"spray"}
```

`/spray_gun/status` (`std_msgs/String`, JSON, 권장 20 Hz):

```json
{"session_id":"동일 UUID","command_id":1,"is_on":false,"ready":true,"fault":""}
```

어댑터는 다음을 구현해야 한다.

- 실제 출력을 제어하고, 실제 적용 상태를 `is_on`으로 회신한다. session/command를 단순히 되비추는 모의 노드는 실기 어댑터로 사용하지 않는다.
- OFF 명령, 연결 종료, fault, 명령 수신 중단 250 ms 이내에 출력 OFF를 적용한다. OFF는 새로운 세션의 첫 명령으로도 수용하고, 같은 세션에서 낮은 command_id의 늦은 ON을 거부한다.
- 새 세션은 OFF 상태에서만 등록한다. 재시작·연결 복구 시 출력은 OFF이다.
- executor는 실제 FJT goal 승인 후 도포 궤적 동안 ON을 요청하고 결과/거부/오류/취소 시 OFF를 요청한다. 최대 약 50 ms 소프트웨어 주기와 실제 밸브 지연이 있으므로 물리적 분사 타이밍은 장치 연결 후 검증한다.
- 상태가 300 ms 이상 끊기거나 출력 확인이 맞지 않으면 정지한다. 출력 전환에는 최대 250 ms의 확인 유예가 있다.

평면 제어 토픽: `/perception/target_planes`, `/painting_system/select_planes`, `/painting_system/planes`, `/painting_system/activate_plane`.
모드 요청은 `/painting_system/set_process_mode`의 문자열 `paint` 또는 `spray`, 확정 상태는 `/painting_system/process_mode` JSON이다. 실행 중에는 모드·평면 변경을 거부한다.

## 이전 검증 기록

아래 기록은 기존 D405 기반 기능의 과거 검증이며 현재 ZED 전용 Spray의 실기 검증을 뜻하지 않는다.

새 기능의 기하, 다중 면 식별/측정 순서, 뿜칠 경로 계약, F/T 모드 분리, gun 상태 전환을 오프라인 테스트했다. 브라우저는 모의 ROS 데이터로 후보 표시/선택 및 모드 전환을 확인했고, ROS domain 218에서 노드 초기화와 모드 왕복을 확인했다. 실제 로봇 이동·벽 접촉·분사는 수행하지 않았다.

전체 기존 회귀 테스트 중 접촉 탐색 취소와 테스트 fixture 관련 10건은 변경 전 원본에서도 실패한다. 이번 작업에서는 기존 접촉 제어 동작을 바꿔 이 실패를 숨기지 않았다. 최종 테스트 수치는 작업 결과 보고를 참조한다.

### 측정 이동 개선 검증 (2026-09-21)

- D405 접근·정밀화·다중 면·뿜칠 관련 테스트 86개 통과(신규 16개 포함).
- 전체 회귀 검사: 436개 통과, 기존 접촉 도장 테스트 10개 실패.
  실패한 동일 10개는 수정 전 운영 코드에서도 재현됨.
- 격리 ROS domain 223에서 실제 ROS 메시지로 중심에서 1.5 m 떨어진 측정점을 요청하고,
  합성 점군 한 프레임(625점)의 평면 적합 및 대상 stamp 일치 확인.
- 실로봇 이동, 실제 카메라 깊이 품질, 실제 이동량 감소는 아직 시험하지 않음.
